# Les conventions d'équipe

Afin d’assurer une organisation efficace entre les quatre développeurs, des conventions Git et Pull Requests sont mises en place. Les nouvelles fonctionnalités doivent etre développées sur des branches dédiées en utilisant les préfixes `feature/`, `fix/` ou `chore/` pour isoler le developpement de la branche principale `main`. Les messages de commit doivent suivre également une convention claire avec des préfixes comme `feat:`, `fix:`, `test:`, `docs:`, `ci:` et `chore:` pour rendre le commit explicite. Toutes les modifications doivent être proposées via une Pull Request avant d’être intégrées à la branche `main`. Chaque Pull Request doit présenter les modifications réalisées, leur objectif ainsi que les éventuels points nécessitant une vérification. Le CI doit être exécuté afin de vérifier automatiquement que les changements respectent les exigences du projet. Une revue de code par au moins un autre développeur est obligatoire avant toute fusion. Cette revue permet notamment de vérifier la qualité du code, les tests réalisés et les éventuels problèmes de sécurité. La fusion dans `main` n’est effectuée que lorsque le CI est réussi et que la revue de code est validée, donc s'assurer que les contrôles automatisés, notamment les tests, sont réussis avant le merge.
Enfin, le recours au **Squash and merge** permet de conserver un historique de la branche `main` simple, propre et lisible.
